# 第四章 地址空间实验报告

## 功能总结

在启用 Sv39 分页后，重写了获取时间和任务追踪两个系统调用。时间可以写回跨页的用户缓冲区，追踪操作按用户页权限读写单个字节，调用次数按任务统计。实现匿名内存映射与解除映射，支持检查区间重叠和物理页不足，也能只释放映射的中间几页。

## 实现说明

### 用户地址与系统调用

第三章里可以直接解引用用户指针。第四章进入系统调用后，内核已经切换到自己的页表，同一个虚拟地址在两张页表里可能指向不同的物理页。内核用 `current_user_token()` 找到当前任务的页表，再按用户的虚拟地址查找物理页。

`sys_get_time` 的第一个参数指向用户准备好的 `TimeVal`，第二个时区参数在本实验中不用。内核读取一次微秒数，用除法和取余得到秒数和不足一秒的微秒数，再按结构体中的顺序写回。若第一个字段恰好位于一页末尾，第二个字段就落在下一页，两页在物理内存中可能不相邻。`translated_byte_buffer` 将这段用户空间按页拆成切片，内核按每个切片的长度推进写入位置。这里沿用框架对调用方提供有效、可写缓冲区的约定。

| `sys_trace` 请求值 | 本章处理方式 |
| --- | --- |
| 0 | 检查地址是规范地址，页表项有效且有 U、R 权限，返回页内偏移处的一个无符号字节。检查失败返回 `-1`。 |
| 1 | 检查地址及 V、U、W 位，将 `data` 的低八位写到指定字节，成功返回 `0`，检查失败返回 `-1`。 |
| 2 | 按系统调用编号查询当前任务的计数，编号超出计数数组范围时返回 `0`。 |
| 其他值 | 返回 `-1`。 |

每个任务在自己的 `TaskControlBlock` 中保存一份计数数组，任务创建时清零。计数发生在系统调用分发之前，所以查询 `trace` 本身时，本次查询已经计入。另一个细节是，`translate` 找到末级页表时，即使目标表项为空也可能返回 `Some`，因此读写和重叠判断都要看表项的 V 位。

### 申请与释放匿名页

`sys_mmap`（222）先检查起点是否按 4096 字节对齐、`prot` 是否只使用低三位且至少有一位置位，再检查地址加法溢出和 Sv39 地址范围。参数有效时，长度为零直接返回 `0`。其余请求将末端向上取整到页边界，把 `prot` 的三位移到页表项的 R、W、X 位置，并加上 U 位。

映射前，`MemorySet` 检查区间内已有的映射，并将所需数据页和新建下级页表所需的物理页一起计入预算。例如，只剩一个物理页帧时，在已有末级页表的空槽上仍可能映射一页，但在需要新建末级页表的位置就会失败。检查通过后才建立 `MapArea`，所以内存不足返回 `-1` 时不会留下半段映射。

`sys_munmap`（215）先检查整段都是有效用户页，再处理与它相交的 `MapArea`。例如原来映射了 A、B、C 三页，只释放 B 时，先把 C 和它的页帧记录拆到右侧，再从左侧区域移除 B。A、C 的物理页和原有数据都保留，B 的页表项被清空，其 `FrameTracker` 析构时归还物理页。这个做法也能处理一次释放跨过两个相邻区域的情况。`sbrk` 单独记录堆顶，因此堆中间被解除映射后，仍能从原堆顶继续增长。

## 简答题

### Sv39 的页表项由什么组成

一个页表项占 8 字节。位 53–10 保存物理页号 PPN，从高到低分为 26、9、9 位。非叶项的 PPN 指向下一级页表，叶项的 PPN 用于定位映射的物理页。位 9–8 是供软件使用的 RSW。位 63–54 留给扩展或保留，本实验置零。低八位的作用如下。[RISC-V 特权架构手册，Supervisor ISA](https://docs.riscv.org/reference/isa/v20260120/priv/supervisor.html)

| 位 | 标志 | 作用 |
| --- | --- | --- |
| 0 | V | 表项有效。V 为 0 时，硬件不能用它完成翻译。 |
| 1、2、3 | R、W、X | 分别控制读、写和取指。有效项三位全零时指向下一级页表。R 为 0 且 W 为 1 是保留编码，硬件访问会触发页故障。 |
| 4 | U | 允许用户态按该页的读、写、执行权限访问。内核私有页清除此位。 |
| 5 | G | 全局映射，可在不同地址空间间共享对应的地址翻译。 |
| 6 | A | 记录页面已被读、写或取指访问。 |
| 7 | D | 记录页面已经被写入，可用于决定换出时是否需要写回。 |

### 缺页时会发生什么

缺页属于同步异常，`scause` 的最高位为 0。异常码 12 表示取指页故障，13 表示读页故障，15 表示写或原子操作页故障。例如 `ch4_mmap1` 给页面设置只读权限，接着向它写入，触发的就是写页故障。

陷入 S 态时，`sepc` 保存出错指令的地址。在本实验的 QEMU 上，`stval` 给出触发页故障的虚拟地址，所以能分别查到“哪条指令”和“访问了哪里”。`sstatus.SPP` 记录先前特权级，从用户态陷入时为 U，原 SIE 复制到 SPIE，SIE 清零。处理器按 `stvec` 进入陷阱入口，此时 `satp` 仍指向原来的页表，随后由入口汇编切换。

### 按需分配能节省多少，怎样处理缺页

假设进程申请连续的 10 GiB，只访问其中 1 MiB。按需分配时，申请阶段只登记虚拟区间和权限，后续只给实际访问的页分配页帧。这样可以节省数据页、页表页和清零时间。文件映射也可推迟磁盘读取，进程退出时从未访问的部分就无需读入。

按 4 KiB 小页计算，10 GiB 包含 2,621,440 页，每张页表能装 512 项。若区间起点按 1 GiB 对齐，完整映射需要 5,120 张末级表、10 张中间表和 1 张根表，页表本身约占 **20 MiB**（精确值为 20 MiB 加 44 KiB）。起点未对齐会略微改变边界处的表数。数据页占用另算。

要实现按需分配，可在每个地址空间记录已申请区间、允许的访问类型，以及匿名页或文件偏移等来源。缺页时，根据 `stval` 和 `scause` 查区间、查权限。合法的首次访问分配页帧，匿名页清零，文件页读取对应内容，然后安装页表项、同步地址翻译缓存，并保持 `sepc` 不变以重试原指令。越界或违反权限时终止该任务。本次实现的匿名映射在 `mmap` 返回前就分配了页帧。

### 换出到磁盘后怎样表示

内核把已换出页的 PTE 标为无效（V 为 0），并在软件记录中保留换出位置和原权限。仅凭 V 为 0 无法区分已换出、尚未分配和从未申请。再次缺页时查记录，已换出的页从对应磁盘位置读回，恢复映射后重试原指令。

### 单页表和双页表分别何时切换

采用单页表时，每个进程的页表同时映射自己的用户页和内核页。内核页的 U 位置零，用户态对这些页取指、读或写都会触发异常。同一进程发生系统调用和返回时可以沿用这张表，节省写 `satp` 和同步地址翻译缓存的开销。调度到不同地址空间时，再把新页表的根物理页号等信息写入 `satp`，按地址空间标识（ASID）的使用情况执行 `sfence.vma`。同一地址空间的线程之间可以沿用原页表。

本章采用双页表。用户陷入时，`__alltraps` 在两个地址空间都映射的跳板页上运行，保存用户寄存器后切到内核页表。返回用户态时，`__restore` 先切到即将运行任务的用户页表，再恢复寄存器并执行 `sret`。两处写 `satp` 后都执行 `sfence.vma`。这样用户页表只需保留陷阱入口和上下文等少量内核相关映射，代价是每次进出内核都要切表。

## 测试结果与运行方法

在仓库根目录准备好 README 指定的官方检查器和测试程序后，执行以下命令。检查器编译基础与作业测例，启动 QEMU，检查串口输出及历次报告。

```bash
make -C ci-user test CHAPTER=4
```

| 用例 | 检查的行为 |
| --- | --- |
| `ch3_sleep`、`ch3_sleep1`、`ch3_trace`、`ch4_trace1` | 获取时间、按任务计数，以及用户页的单字节读写权限。 |
| `ch4_mmap0`、`ch4_mmap3` | 匿名页读写成功。重叠区间、未对齐的起点和无效权限均返回失败。 |
| `ch4_mmap1`、`ch4_mmap2` | 向只读页写入，以及读取设置为仅写的页，均在用户态触发页故障。 |
| `ch4_unmap`、`ch4_unmap2`、`ch4b_sbrk` | 解除和再次建立映射、拒绝含空洞的释放请求，以及堆伸缩后的访问行为。 |

本地使用 QEMU 8.2.2、仓库自带的 RustSBI 0.4.1 和 `nightly-2024-05-02`，运行了 21 个用户程序，通过官方检查器的全部 **16/16** 项输出检查。这里的 16 包含应当出现和禁止出现的输出。检查器找到 `lab1.md` 和 `lab2.md` 后正常退出，`cargo fmt -- --check` 也通过。

另外用三个连续页检查了从中间解映射后两侧的数据，并在限制剩余物理页帧的条件下检查了建页表的额外开销和解除映射后的页帧再利用。
