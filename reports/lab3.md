# 第五章 进程管理实验报告

## 功能总结

迁移获取时间、匿名映射和解除映射，使它们通过当前进程的地址空间工作。实现 spawn，从指定程序创建子进程并返回 PID。实现优先级设置和 stride 调度，通过线性扫描选择累计 stride 最小的就绪任务。保留父子进程关系，使新进程能够正常退出并由父进程等待回收。

## 实现说明

### 从当前进程访问内存

第五章把会变化的进程状态放进 `TaskControlBlockInner`。系统调用先通过 `current_task()` 取得当前进程，再用 `inner_exclusive_access()` 借用内部状态，就能访问它的 `memory_set`。`sys_get_time` 继续按秒和微秒组织字节，通过 `translated_byte_buffer` 按页写回用户缓冲区。

`mmap` 检查起点对齐、权限和已有映射，再分配物理页并登记 `MapArea`。`munmap` 先检查整段的 V、U 标志，再处理与它相交的区域。释放中间几页时，先移出右侧页的原有 `FrameTracker`，随后缩短左侧区域。被移除的 tracker 自动归还物理页，保留页的内容和权限继续有效。

两个调用共享地址区间校验，拒绝整数加法溢出、非规范地址和跨越 Sv39 地址空洞的区间。`MemorySet` 在映射前同时计算数据页和缺少的下级页表所需的物理页帧，预算不足就返回失败。堆伸缩按逻辑堆顶计算增减页，因此堆中间被 `munmap` 留下空洞后，仍能继续增长、收缩和再次申请。

### 创建新进程

`sys_spawn` 的编号为 400。它先把用户传入的字符串转换为内核可读的程序名，再调用加载器查找 ELF 数据。找不到程序时返回 `-1`，找到后调用当前进程的 `spawn` 方法。

`spawn` 从目标 ELF 构建地址空间，分配 PID 和内核栈，构造初始陷阱上下文，并把新任务设为 Ready。父进程的 `children` 保存子进程的强引用，子进程通过 `Weak` 记录父进程，避免引用循环。最后把子进程加入就绪队列，把 PID 返回给父进程。子进程退出后，父进程可以用原来的 `waitpid` 获取退出码并回收它。

新程序的入口、用户栈和堆起点都来自此次加载的 ELF。`fork` 则需要复制当前进程的地址空间与执行现场，并让子进程从调用处返回。两种调用在内存构造上的区别决定了 `spawn` 可以直接装入目标程序。

### 选择下一个任务

就绪任务仍保存在 `VecDeque` 中。`fetch` 用 `iter().enumerate()` 遍历队列，同时拿到任务和下标，记录 stride 最小的位置，再用 `remove` 取出该任务。空队列返回 `None`，stride 相同时选靠前的任务。扫描一次的时间复杂度为 O(n)。

每次选中任务后，按 `BIG_STRIDE / priority` 增加它的 stride。优先级越大，增长越慢，在后续比较中获得调度的机会越多。更新放在 `fetch` 选中任务之后，入队只负责保存任务。

新建和 fork 出的任务按课程约定使用初始 stride 0、优先级 16。`BIG_STRIDE` 取 1,000,000,000，整数除法得到零时将步长设为 1，避免超大合法优先级使累计值一直停在原地。优先级超过这个常数时受整数精度限制，无法继续精确区分各自的调度比例。

`sys_set_priority` 的编号为 140，参数小于等于 1 时返回 `-1`，合法时保存优先级并返回该值。读取 priority 和更新 stride 使用同一次 `inner_exclusive_access()`，避免同一个 `RefCell` 在一条表达式中被重复可变借用。

## 简答题

### stride 溢出后会选谁

假设用 8 位无符号整数，两个进程的步长都为 10，当前 p1 的 stride 为 255，p2 为 250。调度 p2 后，数学上的值应为 260。按 8 位回绕计算，保存的值变成 4。直接用无符号整数比较，会继续选 p2，因为 4 小于 255。开启溢出检查时，普通加法还可能直接报错，因此需要明确处理回绕或在接近上限时调整累计值。

### 为什么最大值与最小值之差有界

设 B 为 BigStride。优先级至少为 2，所以每次增加的步长至多是 B/2。初始 stride 都为 0，最大值与最小值之差为 0。

假设调度前所有 stride 都位于区间 [m, m+B/2]。本次选中的是最小值 m，它增加的步长不超过 B/2，更新后仍落在原区间内。其他进程的值保持原样，新的最小值也不会低于 m，因此最大差仍不超过 B/2。这个推理针对从共同初值开始、严格按最小值调度的一组进程。动态加入新进程时，还需要单独考虑新 stride 与已有进程的相对位置。

### 给 BinaryHeap 使用的比较器

假设任意两个 stride 的真实距离小于 2^63，可先做 64 位回绕减法，再把差解释为有符号整数。差为负时，self 在累计运行顺序上更小。Rust 的 `BinaryHeap` 默认弹出比较意义上的最大值，因此这里反转比较结果，使较小的累计 stride 先被取出。

```rust
use core::cmp::Ordering;

impl PartialOrd for Stride {
    fn partial_cmp(&self, other: &Self) -> Option<Ordering> {
        let difference = self.0.wrapping_sub(other.0) as i64;
        Some(0i64.cmp(&difference))
    }
}
```

例如 8 位的 255 与回绕后的 4，相减得到的 251 按 `i8` 解释为 -5，说明 255 对应的真实累计值更小，应先被调度。题目中的 125 和 255 相减得到 126，129 和 255 相减得到 -126，分别表现出题目给出的环形先后关系。上述比较器又为最大堆反转了一次顺序。实际使用 `BinaryHeap<Stride>` 时还要实现 `Eq`、`Ord`，并使它们与 `PartialEq`、`PartialOrd` 一致。这里保留题目要求的 `partial_cmp` 实现。

本次内核使用线性扫描和普通整数比较，以上比较器作为问答分析。实验内的运行时长远低于累计 stride 溢出的时间尺度。
